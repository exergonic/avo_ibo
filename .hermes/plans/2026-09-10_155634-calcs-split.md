# `calcs.py` Module-Split Implementation Plan

**Goal:** Split `src/avogadro_ibo/calcs.py` (1,798 lines) into six focused modules with zero behavior change, keeping `calcs.py` as a re-export shim.

**Architecture:** Pure file moves — no signature changes, no renames, no logic edits. Each new module owns one pipeline stage; `api.py` owns the `IBOResult` dataclass plus `compute_ibo_data`/`compute_ibo`; `calcs.py` becomes imports + `__all__` only. Inertness is proven by sha256 parity of every `ibos.txt` plus the full pytest suite after each move.

**Tech Stack:** Python ≥3.11, Psi4 (in-process), numpy, pytest, pixi env `.pixi/envs/default/python.exe`. Tier-1 annotations move with their functions untouched.

## Risks, tradeoffs, open questions

- **Risk: silent behavior drift via import cycles.** Mitigation: the dependency graph is a DAG (`api` → all; `analysis` → `constants`; leaves → nothing). If a cycle appears during extraction, STOP and report — it means a helper was misplaced, not that cycles are acceptable.
- **Risk: patch-tool indentation mangling** (known history in frontier/Wiberg region). Mitigation: Task 4 moves by exact cut + `diff` verification, never retype; prefer `git mv`-style block moves via python script over patch-tool edits for the large blocks.
- **Tradeoff: six modules vs fewer.** Four would do (`core`, `analysis`, `molden`, `api`), but the six-way split mirrors the mathematics.md section structure (§-per-stage), which is the documentation a JCE reviewer will cross-check.
- **Explicitly out of scope:** signature changes, renames, purity refactors of the adapter, typing-tier escalation, trajectory plugin, CHANGELOG/1.0 mechanics (separate task after merge).
- **Open question for the user:** merge target — branch + PR review, or direct-to-master per commit as usual? Default in Task 7 is branch; override only on explicit instruction.
